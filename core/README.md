# core

The modules more than one thing here depends on. Nothing in this folder knows
about the board, the companion or the nightly agent; all three know about it.

| | |
| --- | --- |
| `todo.js` | Reading and writing `todo.md`, in JavaScript, for the board. The authority for the format. |
| `todo.py` | The same reading in Python, for everything that is not the board: the two tag syntaxes, the `repeat:` grammar, occurrence maths, dependency resolution, suggested messages, and the UK and Portuguese working calendars. |
| `windows.py` | The rolling 5-hour usage windows: reconstructing them from the transcripts on disk, and deciding whether the nightly agent may spend right now. |
| `fixtures/` | Three JSON tables, generated by running the board's own functions. Both suites below read them; neither holds a table of its own. |
| `test_todo.py` | Those tables against `todo.py`, plus the working calendars. |
| `test_todo.mjs` | The same tables against `todo.js`, plus what the board writes. |

```
python3 core/test_todo.py            the pinned tables
node core/test_todo.mjs              the same tables, the other language
python3 core/test_todo.py --online   and again against gov.uk and Nager.Date
python3 core/windows.py --history    the last 30 days of usage windows
```

## Why it exists

Every file here started inside the thing that first needed it, and outgrew it.

`todo.py` lived in `kanban/` while the board was its only caller. That stopped
being true when the companion imported it, and by the time the pa-checkin checker
and the nightly agent did too, four things depended on a module filed inside one
of them. `windows.py` lived in `nightly/` for about six hours, until the board
wanted the same window history for its Schedule view. `todo.js` was 440 lines in
the middle of `kanban/index.html`, which is a 9,500-line file — one caller, so by
the rule above it had every right to stay there, except that it is the half of
the format the Python is a port *of*. It belongs beside what copies it.

The rule this repo already follows for `data/` — no tools in the data, no data in
the tools — applies to shared code the same way. A module three things import
belongs beside them, not inside one of them.

## What is not here

**Writing `todo.md`.** `todo.py` parses and never serialises, deliberately. The
board keeps every blank line, rule and stray note verbatim so a save that changed
nothing gives back the same bytes, and reproducing that is a whole second
problem. A reader that cannot write also cannot corrupt the file, which is worth
more than the symmetry.

**Policy.** Which tasks are *owed* is `companion/digest.py`'s question, which are
worth *planning* is `nightly/pick.py`'s, and both are answered on top of this
rather than inside it. The test is whether two callers would want the same
answer: the `repeat:` grammar yes, "is this due today" no.

**Anything about a dataset.** These modules take text and return facts. Where
`todo.md` lives is the caller's problem — `nightly/paths.py` for the agent,
`digest.todo_path()` for the companion, `server.py`'s own resolution for the
board — because they genuinely disagree. The companion pins itself to `twinkl` so
switching the board for ten minutes does not change what gets notified tomorrow;
the nightly agent follows `data/.current`.

## The two copies, and what stops them drifting

The board is a single HTML page and cannot import Python, so the format is
understood twice: `todo.js` and `todo.py`, side by side. **Where the two disagree
the board is right and the Python is the bug** — `todo.js` is what actually
writes the file, so its reading is the only one that has to be true.

`fixtures/` is what proves they agree, and it is deliberately not written in
either language:

| | |
| --- | --- |
| `repeat.json` | 30 tag forms, each asked for its next occurrence from 7 days in each of 14 months, then walked 12 occurrences from a fixed anchor. 2,400 dates. |
| `messages.json` | The suggested-message notes, curly quotes and a colon inside the text and a message written without quotes at all, plus a document where the indent decides whether a message serves the task or one step inside it. |
| `parse.json` | A task line carrying every tag, the junk-input edges, and what the board writes back for each — the last of which only `test_todo.mjs` can check, since `todo.py` has no serialiser. |

Every table was generated by running the board's own functions, so they hold the
board's answers rather than a second opinion. Both suites read the same files, so
one change to the grammar is expressed once and fails in both languages.

Writing `parse.json` found three places the two had already drifted, all of them
junk or unreachable input, which is exactly why nobody had noticed: `****` as a
title, a `rank:` with something after the number, and a numbered bucket written
below the Context section. The Python moved in all three.

A fourth turned up hours later and was not junk input at all. `parse_doc` broke
out of the bucket loop on any `## ` heading, which is right *inside* the buckets
and wrong before them — so it stopped at `## How this works`, the first heading
in the real file, and returned zero tasks. Every Python reader went quiet at
once: the companion said nothing was due, the nightly agent had nothing to plan,
the checker found nothing to check. None of them errored, because an empty
document is a valid one.

The board was never affected — `parseDoc` skips everything before the first
numbered bucket into `doc.pre`, and the Python line is the port of that. Which is
the whole argument for these fixtures, and also the argument for what the two
documents in `parse.json` were missing: both of them started at `## 1. People`,
so neither had a preamble to get wrong. The third one does.

There used to be a third copy, hand-transcribed inside
`skills/pa-checkin/scripts/check_todo.py`. It is gone: the checker imports this
file from the repo, or the copy `skills/build.command` stages beside it in the
zip, whichever it can reach. **Do not commit a copy of `todo.py` under
`skills/`** — one copy in git, staged at build time, is the point.

So: after changing either file, run both suites, and after changing `todo.py` run
`skills/build.command` too, so the staged copy in `skills/dist/pa-checkin.skill`
is not left behind.

## One thing about todo.js in particular

The board loads it as a **classic** `<script>`, before its own inline one. That
is not incidental. A classic script's top-level declarations land in the shared
global lexical environment, which is how the board's inline script sees
`parseDoc` and `MSG_NOTE` without a single import; a module would be deferred
past that inline script instead, and every symbol would be missing at the moment
it is first needed.

The same rule is why `todo.js` never touches `window`, `document` or `state`:
`test_todo.mjs` runs it in a bare `vm` context that has none of them. Anything
needing the page belongs in `index.html`, not here.
